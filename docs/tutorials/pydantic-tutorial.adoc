== Einführung in Pydantic

=== Was ist Pydantic?

Pydantic ist eine leistungsstarke Python-Bibliothek für Datenvalidierung und -einstellungen, die auf Python-Typannotationen basiert.
Anders als traditionelle Validierungsansätze nutzt Pydantic das native Python-Typsystem, um sicherzustellen, dass Ihre Daten korrekt und konsistent sind.

*Warum Pydantic verwenden?*

* **Sicherheit**: Validiert Daten automatisch gegen definierte Typen und Einschränkungen
* **Lesbarkeit**: Nutzt Standard-Python-Typannotationen für klaren, verständlichen Code
* **Performance**: Implementiert in Rust und optimiert für Geschwindigkeit
* **Integrationsmöglichkeiten**: Lässt sich hervorragend in moderne Frameworks wie FastAPI integrieren
* **Produktivität**: Reduziert Code und Fehler durch automatische Typkonvertierung und Validierung

=== Reales Beispiel: Online-Bestellsystem

Stellen wir uns vor, Sie entwickeln ein Online-Bestellsystem für ein Restaurant.
Ohne eine Validierungsbibliothek müssten Sie manuell prüfen, ob alle erforderlichen Felder vorhanden sind, ob die Telefonnummer gültig ist, ob die Bestellmenge positiv ist, usw.

Mit Pydantic definieren Sie einfach ein Modell mit Typannotationen:

[source,python]
----
from pydantic import BaseModel, Field, EmailStr
from typing import List, Optional
from datetime import datetime

class MenuItem(BaseModel):
    id: int
    name: str
    price: float = Field(gt=0)
    description: Optional[str] = None

class Order(BaseModel):
    customer_name: str
    email: EmailStr
    items: List[MenuItem]
    total: float = Field(gt=0)
    address: str
    order_time: datetime = Field(default_factory=datetime.now)
    special_instructions: Optional[str] = None
----

Pydantic validiert dann automatisch alle eingehenden Daten gegen dieses Modell und wandelt sie in die richtigen Typen um.

== Grundlegende Konzepte

=== Modelle und Felder

Das Herzstück von Pydantic sind Modelle, die Datenstrukturen repräsentieren.
Jedes Modell erbt von `BaseModel` und definiert Felder mit Typannotationen.

[source,python]
----
from pydantic import BaseModel, Field
from typing import Optional, List
from datetime import date

class Buch(BaseModel):
    isbn: str = Field(..., min_length=10, max_length=13)
    titel: str
    autoren: List[str]
    seitenzahl: int = Field(gt=0)
    erscheinungsdatum: date
    verfügbar: bool = True
    beschreibung: Optional[str] = None
    preis: float = Field(gt=0)
    
    class Config:
        # Zusätzliche Konfigurationsoptionen
        title = "Buchmodell für die Bibliotheksverwaltung"
----

In diesem Beispiel verwenden wir:

* **Field**: Für zusätzliche Validierungsregeln wie Min/Max-Länge und Wertebereiche
* **...**: Als Standardwert bedeutet, dass ein Feld erforderlich ist
* **Optional**: Für Felder, die `None` sein dürfen
* **List**: Für Listen von Werten
* **Config**: Eine innere Klasse für zusätzliche Konfigurationsoptionen

== Fortgeschrittene Validierung

=== Benutzerdefinierte Validatoren

Pydantic erlaubt benutzerdefinierte Validierungslogik mit Validatoren:

[source,python]
----
from pydantic import BaseModel, validator, root_validator
from typing import List
import re

class Kreditkarte(BaseModel):
    nummer: str
    inhaber: str
    ablaufdatum: str
    sicherheitscode: str
    
    @validator('nummer')
    def validate_card_number(cls, v):
        # Entferne Leerzeichen und Bindestriche
        v = re.sub(r'[\s-]', '', v)
        
        # Prüfe, ob nur Ziffern und richtige Länge
        if not v.isdigit() or len(v) != 16:
            raise ValueError('Kreditkartennummer muss 16 Ziffern enthalten')
        
        # Einfache Luhn-Algorithmus-Implementierung
        summe = 0
        für_verdopplung = False
        
        for ziffer in reversed(v):
            ziffer = int(ziffer)
            if für_verdopplung:
                ziffer *= 2
                if ziffer > 9:
                    ziffer -= 9
            
            summe += ziffer
            für_verdopplung = not für_verdopplung
            
        if summe % 10 != 0:
            raise ValueError('Ungültige Kreditkartennummer (Luhn-Check fehlgeschlagen)')
            
        # Maskieren der Kartennummer für die Sicherheit
        return f"{'*' * 12}{v[-4:]}"
    
    @validator('ablaufdatum')
    def validate_expiry_date(cls, v):
        # Prüfe das Datumsformat MM/YY
        if not re.match(r'^(0[1-9]|1[0-2])/[0-9]{2}$', v):
            raise ValueError('Ablaufdatum muss im Format MM/YY sein')
        return v
    
    @validator('sicherheitscode')
    def validate_security_code(cls, v):
        # Prüfe, ob der Sicherheitscode 3 oder 4 Ziffern hat
        if not re.match(r'^[0-9]{3,4}$', v):
            raise ValueError('Sicherheitscode muss 3 oder 4 Ziffern haben')
        return v
    
    @root_validator
    def check_card_data(cls, values):
        # Prüfe, ob der Karteninhaber auf der Karte steht
        if 'inhaber' in values and 'nummer' in values:
            if len(values['inhaber']) < 2:
                raise ValueError('Karteninhaber-Name ist zu kurz')
        return values
----

In diesem Beispiel:

* `@validator` dekoriert Methoden, die einzelne Felder validieren
* `@root_validator` validiert mehrere Felder gleichzeitig
* Die Validatoren können Werte verändern (z.B. Maskierung der Kreditkartennummer)
* Validierungsfehler werden durch das Auslösen von `ValueError` signalisiert

Testen wir die Validierung:

[source,python]
----

    karte = Kreditkarte(

=== Komplexe Datenstrukturen

Pydantic unterstützt verschachtelte Modelle und komplexe Datenstrukturen:

[source,python]
----
from pydantic import BaseModel, Field, HttpUrl
from typing import List, Dict, Optional, Set
from datetime import datetime
from enum import Enum

class BewertungsSterne(int, Enum):
    EINS = 1
    ZWEI = 2
    DREI = 3
    VIER = 4
    FÜNF = 5

class Adresse(BaseModel):
    straße: str
    hausnummer: str
    plz: str
    ort: str
    land: str = "Deutschland"

class Bewertung(BaseModel):
    benutzer_id: int
    sterne: BewertungsSterne
    kommentar: Optional[str] = None
    datum: datetime = Field(default_factory=datetime.now)

class Restaurant(BaseModel):
    id: int
    name: str
    küchen: Set[str]  # Keine Duplikate erlaubt
    adresse: Adresse
    öffnungszeiten: Dict[str, List[str]]  # z.B. {"Montag": ["11:30-14:30", "18:00-22:00"]}
    website: Optional[HttpUrl] = None
    bewertungen: List[Bewertung] = []
    durchschnittliche_bewertung: Optional[float] = None
    
    def aktualisiere_durchschnitt(self):
        if not self.bewertungen:
            self.durchschnittliche_bewertung = None
            return
            
        sterne_summe = sum(bewertung.sterne for bewertung in self.bewertungen)
        self.durchschnittliche_bewertung = round(sterne_summe / len(self.bewertungen), 1)
----

=== Konfigurationsdateien verarbeiten

Pydantic eignet sich hervorragend zum Verarbeiten von Konfigurationsdateien:

[source,python]

import json
from pydantic import BaseModel, Field, ValidationError
from typing import Dict, List, Optional
from enum import Enum

class LogLevel(str, Enum):
    DEBUG = "debug"
    INFO = "info"
    WARNING = "warning"
    ERROR = "error"

class DatabaseConfig(BaseModel):
    host: str
    port: int = 5432
    username: str
    password: str
    database_name: str
    ssl_enabled: bool = False
    connection_timeout: int = 30
    max_connections: int = 100

class LoggingConfig(BaseModel):
    level: LogLevel = LogLevel.INFO
    file_path: Optional[str] = None
    rotate_daily: bool = True
    max_file_size_mb: int = Field(default=10, ge=1, le=1000)

class ServiceConfig(BaseModel):
    name: str
    host: str = "localhost"
    port: int
    workers: int = Field(default=4, ge=1, le=32)
    timeout: int = 30
    dependencies: List[str] = []

class AppConfig(BaseModel):
    debug_mode: bool = False
    environment: str
    database: DatabaseConfig
    logging: LoggingConfig
    services: Dict[str, ServiceConfig]
    allowed_origins: List[str] = ["http://localhost:8080"]
    secret_key: str

        print(f"Konfigurationsfehler: {e}")

        print(f"Fehler beim Laden der Konfiguration: {e}")

=== Daten für maschinelles Lernen strukturieren

Pydantic kann auch verwendet werden, um Daten für ML-Modelle zu strukturieren:

[source,python]
----
from pydantic import BaseModel, Field, validator
from typing import List, Optional, Dict, Union, Literal
import numpy as np
from datetime import datetime

class NumericFeatures(BaseModel):
    alter: int = Field(..., ge=0, le=120)
    einkommen: float = Field(..., ge=0)
    kreditwürdigkeit: float = Field(..., ge=300, le=850)
    bisherige_kredite: int = Field(..., ge=0)
    beschäftigungsdauer_jahre: float = Field(..., ge=0)
    
    # Numpy-Arrays für das ML-Modell erstellen
    def as_array(self) -> np.ndarray:
        return np.array([
            self.alter,
            self.einkommen,
            self.kreditwürdigkeit,
            self.bisherige_kredite,
            self.beschäftigungsdauer_jahre
        ])

class KategorischeFeatures(BaseModel):
    bildungsabschluss: Literal["kein_abschluss", "hauptschule", "realschule", "abitur", "bachelor", "master", "doktor"]
    beschäftigungsstatus: Literal["vollzeit", "teilzeit", "selbstständig", "arbeitslos", "student", "rentner"]
    wohnsituation: Literal["miete", "eigentum", "bei_eltern", "wg"]
    familienstand: Literal["ledig", "verheiratet", "geschieden", "verwitwet"]
    
    # One-Hot-Encoding für das ML-Modell
    def one_hot_encode(self, encoders: Dict) -> Dict[str, np.ndarray]:
        result = {}
        for field_name, value in self.dict().items():
            if field_name in encoders:
                encoder = encoders[field_name]
                # Hier würde normalerweise der Encoder verwendet werden
                # Beispiel-Implementation:
                one_hot = np.zeros(len(encoder.categories_[0]))
                index = encoder.categories_[0].tolist().index(value)
                one_hot[index] = 1
                result[field_name] = one_hot
        return result

class Kreditantrag(BaseModel):
    antrag_id: str
    antragsdatum: datetime
    kreditsumme: float = Field(..., gt=0)
    laufzeit_monate: int = Field(..., ge=1, le=360)
    zinssatz: float = Field(..., ge=0, le=100)
    zweck: str
    
    numerische_features: NumericFeatures
    kategorische_features: KategorischeFeatures
    
    # Zusätzliche berechnete Features
    @property
    def monatliche_rate(self) -> float:
        r = self.zinssatz / 100 / 12
        n = self.laufzeit_monate
        return self.kreditsumme * (r * (1 + r) ** n) / ((1 + r) ** n - 1)
    
    @property
    def verhältnis_rate_einkommen(self) -> float:
        monatliches_einkommen = self.numerische_features.einkommen / 12
        return self.monatliche_rate / monatliches_einkommen
    
    @validator('verhältnis_rate_einkommen', check_fields=False)
    def check_income_ratio(cls, v):
        if v > 0.5:
            raise ValueError("Monatliche Rate übersteigt 50% des Einkommens")
        return v

# Beispielverwendung für ein ML-Modell
def kreditantrag_vorbereiten(antrag: Kreditantrag, encoders: Dict) -> Dict:
    """Bereitet einen Kreditantrag für ein ML-Modell vor."""
    
    # Numerische Features als Array
    num_features = antrag.numerische_features.as_array()
    
    # Kategorische Features als One-Hot-Encoded Arrays
    cat_features = antrag.kategorische_features.one_hot_encode(encoders)
    
    # Antragsspezifische Features
    zusätzliche_features = np.array([
        antrag.kreditsumme,
        antrag.laufzeit_monate,
        antrag.zinssatz,
        antrag.monatliche_rate,
        antrag.verhältnis_rate_einkommen
    ])
    
    # Alle Features zusammenführen (in der Praxis würde hier mehr passieren)
    return {
        "antrag_id": antrag.antrag_id,
        "num_features": num_features,
        "cat_features": cat_features,
        "zusätzliche_features": zusätzliche_features
    }

HexColor = NewType('HexColor', str)

class HexColorValidator:
    @classmethod
    def __get_validators__(cls):
        yield cls.validate
    
    @classmethod
    def validate(cls, v):
        if not isinstance(v, str):
            raise TypeError('String erforderlich')
        
        if not re.match(r'^#[0-9A-Fa-f]{6}', v):
            raise ValueError('Ungültiger HEX-Farbcode (Format: #RRGGBB)')
        
        return v.upper()

# Beispiel für ein Modell mit benutzerdefinierten Typen
class Geschäft(BaseModel):
    name: str
    adresse: str
    plz: PLZ
    stadt: str
    öffnungszeiten_start: time
    öffnungszeiten_ende: time
    farbe: HexColor
    bankverbindung: IBAN
    
    @validator('plz')
    def plz_validieren(cls, v):
        if not re.match(r'^[0-9]{5}', v):
            raise ValueError('Ungültige PLZ (5 Ziffern erforderlich)')
        return v
    
    @validator('bankverbindung')
    def iban_validieren(cls, v):
        # Vereinfachte IBAN-Validierung (nur für Deutschland)
        v = v.replace(' ', '').upper()
        if not re.match(r'^DE[0-9]{2}[0-9]{18}', v):
            raise ValueError('Ungültige deutsche IBAN')
        return v
    
    @validator('öffnungszeiten_ende')
    def öffnungszeiten_validieren(cls, v, values):
        if 'öffnungszeiten_start' in values and v < values['öffnungszeiten_start']:
            raise ValueError('Die Öffnungszeit-Ende muss nach der Öffnungszeit-Start liegen')
        return v

=== Dynamische Modellgenerierung

In manchen Fällen müssen Sie Modelle dynamisch zur Laufzeit erstellen:

[source,python]
----
from pydantic import create_model, Field
from typing import Dict, Any, Optional

def create_dynamisches_modell(schema: Dict[str, Any], model_name: str = "DynamischesModell"):
    """Erstellt dynamisch ein Pydantic-Modell basierend auf einem Schema."""
    feld_definitionen = {}
    
    for feldname, feldconfig in schema.items():
        feldtyp = feldconfig.get("typ", str)
        erforderlich = feldconfig.get("erforderlich", True)
        beschreibung = feldconfig.get("beschreibung", "")
        
        # Standardwert basierend auf "erforderlich" festlegen
        default_value = ... if erforderlich else None
        
        # Zusätzliche Validierungsattribute sammeln
        extra_kwargs = {}
        if "min_length" in feldconfig:
            extra_kwargs["min_length"] = feldconfig["min_length"]
        if "max_length" in feldconfig:
            extra_kwargs["max_length"] = feldconfig["max_length"]
        if "regex" in feldconfig:
            extra_kwargs["regex"] = feldconfig["regex"]
        
        # Feld mit Validierungsregeln erstellen
        feld = (
            Optional[feldtyp] if not erforderlich else feldtyp,
            Field(default_value, description=beschreibung, **extra_kwargs)
        )
        
        feld_definitionen[feldname] = feld
    
    # Modell erstellen
    return create_model(model_name, **feld_definitionen)

# Beispiel-Schema für ein Kontaktformular
kontaktformular_schema = {

=== FastAPI

Pydantic und FastAPI sind das perfekte Duo für die API-Entwicklung:

[source,python]
----
from fastapi import FastAPI, HTTPException, Depends, Query
from pydantic import BaseModel, Field, EmailStr
from typing import List, Optional
from datetime import date
import uvicorn

app = FastAPI(title="Buchhandlung API", version="1.0.0")

# Pydantic-Modelle für Request/Response
class BuchBasis(BaseModel):
    titel: str = Field(..., min_length=1, max_length=100)
    autor: str = Field(..., min_length=2)
    isbn: str = Field(..., regex=r"^(?=(?:\D*\d){10}(?:(?:\D*\d){3})?$)[\d-]+$")
    erscheinungsdatum: date
    preis: float = Field(..., gt=0)
    auf_lager: bool = True

class BuchErstellen(BuchBasis):
    pass

class Buch(BuchBasis):
    id: int
    
    class Config:
        orm_mode = True  # Erlaubt die Konvertierung von ORM-Objekten

class BuchUpdate(BaseModel):
    titel: Optional[str] = Field(None, min_length=1, max_length=100)
    autor: Optional[str] = None
    preis: Optional[float] = Field(None, gt=0)
    auf_lager: Optional[bool] = None

# Eine einfache In-Memory-Datenbank für das Beispiel
bücher_db = {}
bücher_zähler = 0

@app.post("/bücher/", response_model=Buch, status_code=201)
def buch_erstellen(buch: BuchErstellen):
    global bücher_zähler
    bücher_zähler += 1
    neues_buch = Buch(id=bücher_zähler, **buch.dict())
    bücher_db[bücher_zähler] = neues_buch
    return neues_buch

@app.get("/bücher/", response_model=List[Buch])
def bücher_auflisten(
    titel: Optional[str] = Query(None, description="Nach Titel filtern"),
    auf_lager: Optional[bool] = Query(None, description="Nur verfügbare Bücher anzeigen")
):
    ergebnis = list(bücher_db.values())
    
    if titel:
        ergebnis = [b for b in ergebnis if titel.lower() in b.titel.lower()]
    
    if auf_lager is not None:
        ergebnis = [b for b in ergebnis if b.auf_lager == auf_lager]
        
    return ergebnis

@app.get("/bücher/{buch_id}", response_model=Buch)
def buch_details(buch_id: int):
    if buch_id not in bücher_db:
        raise HTTPException(status_code=404, detail="Buch nicht gefunden")
    return bücher_db[buch_id]

@app.patch("/bücher/{buch_id}", response_model=Buch)
def buch_aktualisieren(buch_id: int, update_data: BuchUpdate):
    if buch_id not in bücher_db:
        raise HTTPException(status_code=404, detail="Buch nicht gefunden")
    
    buch = bücher_db[buch_id]
    update_dict = update_data.dict(exclude_unset=True)
    
    for key, value in update_dict.items():
        setattr(buch, key, value)
    
    bücher_db[buch_id] = buch
    return buch

@app.delete("/bücher/{buch_id}", status_code=204)
def buch_löschen(buch_id: int):
    if buch_id not in bücher_db:
        raise HTTPException(status_code=404, detail="Buch nicht gefunden")
    
    del bücher_db[buch_id]
    return None

# Server starten (in einer echten Anwendung würde man die uvicorn-CLI verwenden)
if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)

=== Datenverarbeitung mit Pandas

Pydantic kann auch mit Pandas für Datenanalysen kombiniert werden:

import pandas as pd
from pydantic import BaseModel, validator
from typing import List, Optional, Dict
import numpy as np
from datetime import datetime

class Verkauf(BaseModel):
    produkt_id: int
    menge: int
    preis_pro_einheit: float
    verkaufsdatum: datetime
    rabatt_prozent: Optional[float] = 0.0
    
    @validator('menge')
    def menge_positiv(cls, v):
        if v <= 0:
            raise ValueError('Menge muss positiv sein')
        return v
    
    @validator('rabatt_prozent')
    def rabatt_gültig(cls, v):
        if v < 0 or v > 100:
            raise ValueError('Rabatt muss zwischen 0 und 100 Prozent liegen')
        return v
    
    @property
    def gesamtpreis(self) -> float:
        return self.menge * self.preis_pro_einheit * (1 - self.rabatt_prozent / 100)

class VerkaufsAnalyse:
    def __init__(self, verkäufe: List[Verkauf]):
        self.verkäufe = verkäufe
    
    def erstelle_dataframe(self) -> pd.DataFrame:
        """Konvertiert die Verkaufsdaten in einen Pandas DataFrame."""
        daten = []
        for verkauf in self.verkäufe:
            daten.append({
                'produkt_id': verkauf.produkt_id,
                'menge': verkauf.menge,
                'preis_pro_einheit': verkauf.preis_pro_einheit,
                'verkaufsdatum': verkauf.verkaufsdatum,
                'rabatt_prozent': verkauf.rabatt_prozent,
                'gesamtpreis': verkauf.gesamtpreis
            })
        
        return pd.DataFrame(daten)
    
    def tägliche_verkäufe(self) -> pd.DataFrame:
        """Analysiert die Verkäufe nach Datum."""
        df = self.erstelle_dataframe()
        df['datum'] = df['verkaufsdatum'].dt.date
        
        tägliche_stats = df.groupby('datum').agg({
            'menge': 'sum',
            'gesamtpreis': 'sum',
            'produkt_id': 'count'
        }).rename(columns={'produkt_id': 'anzahl_verkäufe'})
        
        return tägliche_stats
    
    def produkt_verkäufe(self) -> pd.DataFrame:
        """Analysiert die Verkäufe nach Produkt."""
        df = self.erstelle_dataframe()
        
        produkt_stats = df.groupby('produkt_id').agg({
            'menge': 'sum',
            'gesamtpreis': 'sum',
            'verkaufsdatum': 'count'
        }).rename(columns={'verkaufsdatum': 'anzahl_verkäufe'})
        
        return produkt_stats

        gt=0,
        description="Preis in Euro",
        examples=[499.99, 999.99]

== Pydantic v2 Features und Migration

Pydantic v2 wurde mit einem Fokus auf Performance und Benutzerfreundlichkeit neu implementiert. In diesem Abschnitt lernen Sie die wichtigsten Neuerungen und Migrationsschritte kennen.

=== Wichtige Neuerungen in Pydantic v2

[source,python]
----
# Pydantic v2 Beispiel
from pydantic import BaseModel, Field, field_validator, model_validator
from typing import List

class Bestellung(BaseModel):
    kunden_id: int
    produkt_ids: List[int]
    gesamtpreis: float = Field(gt=0)
    
    # Neuer Validator-Dekorator in v2
    @field_validator('produkt_ids')
    def validate_product_ids(cls, v):
        if not v:  # Leere Liste
            raise ValueError("Mindestens ein Produkt muss bestellt werden")
        return v
    
    # Ersetzt root_validator in v1
    @model_validator(mode='after')
    def validate_total(self):
        # Hier könnte eine Prüfung des Gesamtpreises erfolgen
        if self.gesamtpreis < len(self.produkt_ids) * 10:  # Mindestpreis pro Produkt
            raise ValueError("Gesamtpreis zu niedrig für die Anzahl der Produkte")
        return self
----

=== Migrationsschritte von v1 zu v2

==== 1. Validatoren umstellen

[source,python]
----
# Pydantic v1
from pydantic import BaseModel, validator, root_validator

class ProduktV1(BaseModel):
    name: str
    preis: float
    
    @validator('name')
    def name_must_be_valid(cls, v):
        if len(v) < 3:
            raise ValueError("Name muss mindestens 3 Zeichen haben")
        return v.title()
    
    @root_validator
    def check_price(cls, values):
        if 'preis' in values and values['preis'] <= 0:
            raise ValueError("Preis muss positiv sein")
        return values

# Pydantic v2
from pydantic import BaseModel, field_validator, model_validator

class ProduktV2(BaseModel):
    name: str
    preis: float
    
    @field_validator('name')
    def name_must_be_valid(cls, v):
        if len(v) < 3:
            raise ValueError("Name muss mindestens 3 Zeichen haben")
        return v.title()
    
    @model_validator(mode='after')
    def check_price(self):
        if self.preis <= 0:
            raise ValueError("Preis muss positiv sein")
        return self
----

== Benutzerdefinierte Typen und komplexe Validierung

In diesem Abschnitt lernen Sie, wie Sie benutzerdefinierte Typen erstellen und komplexe Validierungsszenarien umsetzen können.

=== Benutzerdefinierte Typen

[source,python]
----
from pydantic import BaseModel, validator
from typing import NewType, List, Dict, Any
import re

# Benutzerdefinierte Typen definieren
Postleitzahl = NewType('Postleitzahl', str)
Telefonnummer = NewType('Telefonnummer', str)
IBAN = NewType('IBAN', str)

class Kontakt(BaseModel):
    name: str
    plz: Postleitzahl
    telefon: Telefonnummer
    iban: IBAN
    
    @validator('plz')
    def validate_plz(cls, v):
        if not re.match(r'^\d{5}$', v):  # Deutsche PLZ
            raise ValueError("Ungültiges PLZ-Format. Muss 5 Ziffern enthalten.")
        return v
    
    @validator('telefon')
    def validate_phone(cls, v):
        # Entferne Leerzeichen, Klammern, Bindestriche
        cleaned = re.sub(r'[\s\(\)\-]', '', v)
        if not re.match(r'^(\+\d{1,3})?\d{6,15}$', cleaned):
            raise ValueError("Ungültiges Telefonnummer-Format")
        return cleaned
    
    @validator('iban')
    def validate_iban(cls, v):
        # Vereinfachte IBAN-Validierung
        cleaned = re.sub(r'\s', '', v.upper())
        if not re.match(r'^[A-Z]{2}\d{2}[A-Z0-9]{4,30}$', cleaned):
            raise ValueError("Ungültiges IBAN-Format")
        return cleaned
----

== Tipps und Best Practices

=== Optimierung der Performance

Pydantic bietet mehrere Möglichkeiten zur Leistungsoptimierung:

1. **Verwenden Sie `Config.extra = 'ignore'`**, um zusätzliche Felder stillschweigend zu ignorieren, anstatt einen Fehler auszulösen:

[source,python]
----
class BenutzerEinstellungen(BaseModel):
    theme: str = "hell"
    benachrichtigungen: bool = True
    sprache: str = "de"
    
    class Config:
        extra = 'ignore'  # Ignoriert unbekannte Felder
----

2. **Vermeiden Sie übermäßige Validierung** für Daten, die bereits validiert wurden:

[source,python]
----
# Bei bereits validiertem Objekt
benutzer_dict = bereits_validierter_benutzer.dict()
benutzer_dict["name"] = "Neuer Name"
aktualisierter_benutzer = Benutzer.construct(**benutzer_dict)  # Umgeht Validierung

# Beim Konvertieren zu JSON
json_str = bereits_validierter_benutzer.json()
----

3. **Verwenden Sie `Config.orm_mode = True`** für effiziente ORM-Integration:

[source,python]
----
class BenutzerModell(BaseModel):
    id: int
    name: str
    email: str
    
    class Config:
        orm_mode = True  # Ermöglicht .from_orm()
----

=== Fehlerbehandlung

Effektive Fehlerbehandlung mit Pydantic:

[source,python]
----
from pydantic import BaseModel, ValidationError, Field
from typing import List

class ProduktErstellen(BaseModel):
    name: str = Field(..., min_length=3)
    preis: float = Field(..., gt=0)
    kategorien: List[str]

def produkt_erstellen_handler(daten: dict):
    try:
        produkt_model = ProduktErstellen(**daten)
        # Mit validiertem Modell weiterarbeiten
        return {
            "erfolg": True,
            "produkt": produkt_model.dict()
        }
    except ValidationError as e:
        fehler_details = []
        for fehler in e.errors():
            fehler_details.append({
                "feld": fehler["loc"][0],
                "nachricht": fehler["msg"],
                "typ": fehler["type"]
            })
        
        # Fehlerdetails zurückgeben
        return {
            "erfolg": False,
            "fehler": fehler_details
        }

# Beispielverwendung
gültige_daten = {
    "name": "Premium Laptop",
    "preis": 1299.99,
    "kategorien": ["Elektronik", "Computer"]
}

ungültige_daten = {
    "name": "PC",  # Zu kurz (min_length=3)
    "preis": -99.99,  # Negativer Preis (gt=0)
    "kategorien": "Elektronik"  # String statt Liste
}

print(produkt_erstellen_handler(gültige_daten))
# Erfolgreiche Validierung

print(produkt_erstellen_handler(ungültige_daten))
# Gibt Fehlerdetails zurück
----

=== Bewährte Praktiken für Fehlerbehandlung

1. **Spezifische Fehlermeldungen**: Stellen Sie sicher, dass Ihre Validierungsfehler klar und spezifisch sind.

2. **Strukturierte Fehlerrückgabe**: Geben Sie Fehler in einem strukturierten Format zurück, das leicht zu verarbeiten ist.

3. **Fehlerlokalisation**: Nutzen Sie die `loc`-Information in ValidationError, um genau zu identifizieren, wo der Fehler aufgetreten ist.

4. **Benutzerdefinierte Fehlermeldungen**: Verwenden Sie das `error_msg`-Argument in Field, um benutzerdefinierte Fehlermeldungen zu definieren:

[source,python]
----
class Benutzer(BaseModel):
    name: str = Field(..., min_length=2, error_messages={
        'min_length': 'Der Name muss mindestens 2 Zeichen lang sein.'
    })
----
